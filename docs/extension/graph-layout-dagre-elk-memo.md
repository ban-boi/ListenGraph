# 图谱几何：边锚点与 dagre / elk 布局器备忘

## 目的

本文是**设计备忘**，记录一次对话中关于下列主题的结论与推理，便于日后真要接入专用布局器或继续打磨默认视图时对照：

- 节点排版（手写稳定布局）与渲染层边锚点变更的边界
- dagre / elk 等专用布局器的**真实收益**与**不应期待的能力**
- 与「增量稳定长出」产品形态之间的张力，以及若接入时「何时允许重排」比「选哪个库」更关键

**说明**：本文**不是**当前实现的唯一权威说明；session 内稳定性原则仍以 [扩展增量图稳定性](C:/Users/finni/Desktop/ListenGraph/docs/extension/incremental-graph-stability.md) 为准。代码与行为若有出入，以代码为准。

---

## 节点排版（相对稳定）

节点排版没有变，仍是原先那套前端稳定布局逻辑：

- 旧节点优先复用位置
- 新节点默认沿主轴往下排
- `reason` / `example` / `question` 等分支节点会尝试挂到锚点旁边
- 撞到别的节点就继续往下挪

---

## 渲染层：四向边锚点与 smoothstep

这次变的是**渲染层**的边锚点：

- 节点从原来的上下两个可用锚点，变成了**四向** `source` / `target` handles
- 每条边会根据两个节点的相对几何位置，自动选 `top` / `bottom` / `left` / `right`
- 边类型改成了 **smoothstep**

因此用户可见的变化应主要体现在：

- 同列上下节点更容易表现成 **bottom → top**
- 左右关系更容易走侧边
- 线穿节点、从节点背后竖着出头的情况会少很多

---

## 问答：是否需要接入 dagre / elk？

**结论（备忘）**：值得考虑，但不是「这一步」最该先做的事。当时最刺眼的问题主要是「边怎么接」；这一步已开始修。布局器能带来明显提升，但它解决的是**另一层**问题。

概括：

1. dagre / elk 的核心收益主要是**几何层**和**结构层**，**不是语义层**。
2. 它们不会自动理解「谁支持谁、谁反对谁、谁更重要」——这些仍是模型或规则层的事。
3. 它们会把**已经给定的图结构**排得更像一张真正的图，而不是现在这种「稳定增量列表 + 分支偏移」的近似布局。
4. 若只做默认视图、后面再接布局器有价值，但目标宜定义成「更好看的默认**阅读**图」，而不是「更语义化」。

---

## 专用布局器能解决什么

当前手写布局本质是**稳定增量排版器**：优点是稳，缺点是**图感**相对弱。

专用布局器带来的收益，主要有三类（均为几何 / 结构可读性，而非语义推理）。

### 1. 整体结构更像图，而不是堆卡片

当前节点位置主要由时间顺序、主列向下、分支往右挂、碰撞时向下挪驱动。它不太做全局优化，可能带来：

- 某些边很长
- 某些局部拥挤
- 语义紧密的节点在空间上却较远
- 多条边的交叉与绕行缺少系统考量

dagre / elk 的第一层收益，是把**全局结构**纳入考虑，使父子更靠近、依赖链更顺、边交叉更少、层次更清楚。这是**结构可读性**增强，不是语义增强。

### 2. 边的观感更自然

接点修对之后，若两节点在几何上被摆成别扭的上下/左右关系，线仍会别扭。布局器能改善谁应同层、谁应下一层、横向展开是否更合适、长边能否整体缩短等。布局器不「理解语义」，但能让视觉结构更接近读者脑中的图。

### 3. 复杂图时更抗规模增长

手写规则在小图、增量场景够用；节点变多后，右侧分支发散、碰撞只往下挪导致垂直拉长、早期冻结位置导致后续结构变形等问题会加重。专用布局器为「规模上去仍能读」而设计，在中等复杂度图上通常比纯启发式更稳健。仍是**几何层**收益。

---

## 语义收益有没有？

有，但**很间接**。

布局器本身不懂语义；若先把图的语义关系建对，再给布局器方向与约束，用户会觉得「图更像在表达语义」——例如结论在后理由在前、例子挂论点侧边、反对关系跨到另一侧、主干自上而下。真正发生的是：

1. 语义层提供了结构关系；
2. 布局器把该结构**画得更清楚**。

因此它是**语义结构的视觉放大器**，不是**语义推理器**。

---

## dagre 与 elk 的差别（粗暴理解）

- **dagre**：更轻、更简单，适合先把 DAG / 层次图排顺。
- **elk**：更强、更复杂，约束能力更高，适合更复杂的分组、多种边、spacing / routing、多列泳道等。

结合本项目：

- 若目标是尽快让默认视图**像样**：优先考虑 **dagre**（接入成本相对低，自上而下主干、减交叉、分层通常够用，适合作第一版验证）。
- 若目标是成熟图谱视图、后续强约束多：再考虑 **elk**（更重）。

---

## 与「增量稳定」产品的冲突

短期不必立刻上布局器，备忘理由包括：

1. 刚修的是边锚点，需先看真实效果。
2. 痛点未必已证明来自「布局器不足」，而非接点与路由。
3. 产品重心更像**增量稳定阅读**，与许多布局器「**全局重排**」的天然倾向存在冲突。

**关键张力**：

- 布局器追求全局美观；
- 产品追求增量稳定、不抖。

这不是不能接，但不能「天真」接入。**若未来接入，最核心的设计问题是「什么时候允许重排」**，比选 dagre 还是 elk 更关键。

### 策略备忘

**方案 A：全量重排**  
每次图更新都跑布局器。

- 优点：最整齐、结构最清楚。
- 缺点：老节点会跳，增量阅读体验差，与「稳定长出」方向相悖。**不建议**作为默认。

**方案 B：只对新增子图做局部布局**  
老节点尽量冻结，仅对新增部分及其一跳邻居局部重排。

- 优点：更接近当前交互模型，兼顾局部整洁与整体稳定。
- 缺点：实现复杂，需要自研「布局器输入裁剪 + 结果融合」。**最看好**的方向。

**方案 C：仅在特定时机全量重排**  
例如会话结束、用户点「整理布局」、导出前、从增量模式切到阅读模式。

- 优点：增量时稳定，需要时又能得到更漂亮的全局图。**务实，推荐**与 A 的反面结合使用。

## 可观测收益 vs 不应期待的目标

用布局器可以具体追求、且可观测的收益包括：

- 更少边交叉；
- 节点密度上升后仍可读。

**不建议**把接布局器当成：

- 让模型更聪明；
- 让图自动理解支持 / 反对 / 因果；
- 让默认视图自动变成「真正因果图」。

布局器只能把**已有**图结构画得更好。画不好通常因为：输入结构弱、约束不清、或稳定性要求与全局美观冲突。

---

## 建议优先级（备忘）

1. 先观察「几何锚点 + smoothstep」之后默认视图的真实观感。
2. 若主要剩余问题是「不穿线但整体仍松散/别扭」，再系统讨论布局器。
3. 真要试接：先用 **dagre** 做「仅在整理视图 / 用户触发时使用」的实验版，**不要**直接替换当前增量布局。
4. 仅当实验证明收益很大，再考虑增量稳定融合，乃至升级到 elk。

**一句话**：接 dagre / elk 的价值真实，但核心是**几何与结构可读性**，不是语义本身；它更像**图形排版引擎**，不是**语义理解引擎**。
