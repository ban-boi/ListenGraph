# 扩展增量图稳定性

## 目的
本文记录 extension sidepanel 当前关于“图如何持续长出来”的产品决策与运行时约束。

这份文档关注的是：
- 用户为什么不应该在每次 structing 后看到“另一张图”
- 当前实现如何减少视觉跳变
- 当前实现如何减少历史语义被回写
- 当前仍然存在的边界与已知限制

## 核心产品原则
当前 session 内的图默认被视为一种**增量生成中的阅读对象**，而不是每次重新布局、重新解释的瞬时计算结果。

因此当前默认原则是：
- 图应当尽量表现为“在原图上继续长出新节点和新连线”
- 前面已经出现的节点应保持可识别的位置连续性
- 用户当前选择的 view 不应因后续局部更新而被系统擅自切换
- 系统不应在每次更新时重新抢占 viewport
- 历史节点的语义默认应视为已沉淀，只允许追加，不鼓励回写

一句话概括：

`append to history, not rewrite history`

## 视觉稳定规则
### 1. session 内默认锁定当前 view
当前 sidepanel 在 session 开始时可根据图内容选择一个初始 view，但后续 `MERGED_GRAPH_UPDATED` 不再自动重新跑 `pickDefaultView()`。

当前行为：
- 进入 session 时选择初始 view
- 后续 graph 更新保持当前 view
- 只有用户手动点击“因果 / 时间线 / 对比 / 流程 / 层级”时才切换

这样做是为了避免：
- 新增一条 `example_of` 或 `opposes` 边后整张图突然换成另一种解释结构
- 用户在阅读“同一张图”时，系统把阅读方式一起换掉

### 2. 只首帧自动 `fitView`
`fitView` 只在图第一次出现时自动触发一次，用来把首屏图形框进视口。

当前行为：
- 首次有节点时自动 `fitView`
- 后续 structing 更新不再自动缩放或平移

这样做是为了避免：
- 用户刚盯住某一块内容时，画面被系统强制缩放或拖走
- 即使节点位置稳定，viewport 仍然造成“整张图在跳”的错觉

### 3. 稳定布局优先复用旧坐标
当前 sidepanel 为每个 view 维护位置缓存。

当前行为：
- 老节点若仍存在，优先复用已有坐标
- 新节点按“主轴向下增长、局部侧向展开”放置
- 纯新增边时，已有节点尽量完全不动
- 使用保守碰撞检测避免新节点与已有节点明显重叠

当前结果：
- 用户看到的是旧图保持骨架，新内容局部长出来
- 即使内部 graph 对象整体更新，视觉上仍保持连续性

## 语义稳定规则
### 1. incremental 默认只抽净新增
structurer 当前仍保持：
- `bootstrap` 允许对完整窗口做首版摘要
- `incremental` 只应输出 `latestChunkTranscript` 暗示的净新增

### 2. recentGraphContext 视为冻结语义
对 incremental 来说，`recentGraphContext` 不再只是“可参考上下文”，而是默认视为已冻结的历史语义。

当前约束：
- 不应重述已有节点语义
- 不应改写、改名、扩写、缩写已有节点文本
- 不应把历史节点重新归类成另一种节点类型
- 如果新内容只是补充理由、例子、后果、说明，应新增节点并回连旧节点
- 如果没有净新增语义，应返回空 `nodes` / `edges`

### 3. merge 以历史稳定优先
当前 `mergeSegmentGraph()` 的默认方向已经从“图正确性优先”收紧到“历史稳定优先”。

当前行为：
- 精确重复仍允许折叠
- 高相似度、接近 ASR 噪声的近重复仍允许去重
- 但“更完整的新说法”不应再吞并旧节点
- 合并后只更新 metadata，例如：
  - `confidence`
  - `status`
  - `evidenceChunkIds`
  - 更早时间戳

这样做是为了避免：
- 后面的 structing 把前面节点偷偷改写成另一种表述
- 用户看到节点位置没变，但其语义已经被系统悄悄替换

## 日志与调试语义
当前 sidepanel 不再只输出“当前总节点数”，而是优先输出增量日志，例如：
- `图更新: +1 节点, +2 连线`
- `图更新: 仅新增连线 +1`
- `图更新: 无新增节点/连线`

这样做是为了让日志语义更贴近用户体感：
- 如果肉眼只看到新连线出现，日志也应反映“只是加边”
- 而不是误导成“又整张图全量刷新了”

当前 debug 导出中的 `derivedViews` 也包含布局诊断：
- `reusedPositions`
- `newPositions`
- `movedPositions`

这样可以帮助判断一次更新到底是：
- 复用了多少老节点位置
- 新放置了多少节点
- 是否真的发生了节点移动

## 已知限制
当前稳定性实现仍有几个明确边界：

1. 碰撞检测仍使用固定节点尺寸估算
- 当前是保守估算，不是真实 DOM 测量
- 长文本节点在局部密集场景下仍可能出现轻微间距不准

2. 语义冻结仍是保守冻结
- 当前不是“强冻结”
- 精确重复和高相似度转写噪声仍会被去重
- 这样可以避免明显重复节点爆炸，但也意味着冻结不是绝对禁止一切合并

3. 布局缓存只存在 sidepanel 运行态
- 当前不把节点坐标持久化到 storage 或 service worker
- sidepanel 重开后会重新初始化布局缓存

## 何时需要继续推进
如果后续观察到以下问题，可继续推进第二阶段优化：
- 节点仍偶尔粘得太近：考虑升级为真实节点尺寸测量
- 历史节点虽然位置稳定，但语义仍被过度重解释：继续收紧 merge 或扩大冻结窗口
- 用户需要手动恢复全图视角：补“重置视图 / 重新 fitView”入口
